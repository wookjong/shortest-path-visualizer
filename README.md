# Dijkstra & A* Lab — 최단 경로 탐색 시각화

**▶ 바로 실행 (Live demo): https://wookjong.github.io/shortest-path-visualizer/**

그래프나 격자를 직접 만들고, Dijkstra와 A*가 **이진 최소 힙(우선순위 큐)**에서 키가 가장 작은 노드를 `deletemin`으로 꺼내 확정하고, 이웃 간선을 완화(relax)하는 과정을 **의사코드 한 줄 단위**로 따라가는 웹 페이지입니다.

## 의사코드와 구현 대응

```
function Dijkstra(G, l, s, t)            function A*(G, l, s, t, h)
  for all u ∈ V do                          for all u ∈ V do
      dist(u) = ∞; prev(u) = nil                g(u) = ∞; prev(u) = nil
  dist(s) = 0                               g(s) = 0; f(s) = g(s) + h(s)
  H = makequeue({s})   ▷ key = dist         H = makequeue({s})   ▷ key = f = g + h
  while H is not empty do                   while H is not empty do
      u = deletemin(H)                          u = deletemin(H)
      if u = t then return path(prev)           if u = t then return path(prev)
      for all edges (u, v) ∈ E do               for all edges (u, v) ∈ E do
          if dist(v) > dist(u) + l(u,v)             if g(v) > g(u) + l(u,v)
              dist(v) = dist(u) + l(u,v)                g(v) = g(u) + l(u,v); prev(v) = u
              prev(v) = u; decreasekey(H, v)            f(v) = g(v) + h(v); decreasekey(H, v)
```

**decreasekey는 lazy deletion으로 구현했습니다.**
이진 힙에서 원소의 키를 직접 낮추는 대신, 더 작은 키로 **새 항목을 insert**합니다.
예전 항목은 힙에 남아 있다가(stale) 나중에 deletemin 되면 이미 확정된 노드이므로 **버립니다**(`DELETEMIN · STALE` 연산).
힙 트리에서 같은 노드가 두 번 보이고 하나가 점선+취소선인 경우가 이것입니다.
시간복잡도는 똑같이 `O((|V|+|E|) log |V|)`입니다.

## A*에서 사용한 휴리스틱 정리

A*는 `f(n) = g(n) + h(n)`이 가장 작은 노드부터 확정합니다.
`g(n)`은 시작점부터의 실제 거리이고, `h(n)`은 도착점까지 남은 거리의 **추정치(휴리스틱)**입니다.
`h`가 실제 남은 거리를 **과대추정하지 않으면(admissible)** A*는 최적 경로를 보장합니다.
Dijkstra는 `h(n) = 0`인 A*와 같습니다.
f가 같을 때는 h가 작은(도착점에 가까운) 노드를 먼저 꺼내도록 했습니다.

### 1) 격자 (Grid)

`(r, c)`는 현재 칸, `(r_g, c_g)`는 도착 칸, `dx = |c − c_g|`, `dy = |r − r_g|`입니다.

| 휴리스틱 | 식 | 4방향 이동 (비용 1) | 8방향 이동 (대각선 √2) |
|---|---|---|---|
| **맨해튼** (기본값) | `h = dx + dy` | ✅ **정확한 하한**. 장애물이 없으면 실제 거리와 같고, 가장 적은 노드로 최적 경로를 찾습니다. | ⚠ **과대추정**. 대각선 1칸(√2 ≈ 1.41)을 2로 셈 → admissible 아님 → **최적 경로가 보장되지 않습니다**(화면에 경고 표시). |
| **유클리드** | `h = √(dx² + dy²)` | ✅ admissible. 다만 맨해튼보다 작게 추정해서 노드를 더 많이 탐색합니다. | ✅ admissible. 직선거리는 어떤 경로보다도 짧거나 같으므로 최적 보장. |

정리하면 **4방향에는 맨해튼, 8방향에는 유클리드**가 맞는 조합입니다.
8방향 + 맨해튼은 "빠르지만 최적이 아닐 수 있는" 예시로 쓸 수 있습니다.
기본 예제 맵에서는 결과적으로 비용이 같게 나왔지만 보장되는 것은 아닙니다.

> 대각선 이동은 양옆 두 칸이 모두 비어 있을 때만 허용합니다(벽 모서리를 끼고 지나가지 않음).

### 2) 가중치 그래프 (Graph)

각 노드에 화면 좌표 `(x, y)`가 있어서 **노드 좌표 기반 유클리드 거리**를 사용합니다.

```
h(n) = k × √((x_n − x_goal)² + (y_n − y_goal)²)
k    = min over 모든 간선 (u,v) of  w(u,v) / 직선거리(u,v)
```

- 간선 가중치는 픽셀 길이와 단위가 다르므로(RANDOM 모드: 길이/18 × 1.0~1.8), 직선거리를 그대로 쓰면 h가 과대추정될 수 있습니다.
- 그래서 배율 `k`를 **"모든 간선에서 w ≥ k × 길이"가 성립하는 최대값**으로 잡았습니다. 이러면 어떤 경로든 실제 비용 ≥ k × (경로 길이) ≥ k × (직선거리) = h 이므로 **admissible**합니다.
  삼각부등식 때문에 `h(u) ≤ w(u,v) + h(v)`도 성립해서 **consistent(일관적)**하기도 합니다. 그래서 closed 노드를 다시 열 필요가 없습니다.
- 현재 그래프의 `k` 값은 PSEUDOCODE 카드 아래 HEURISTIC 칸에 표시됩니다(A* 선택 시). 가중치를 직접 고치면 k 도 다시 계산되므로 h 는 항상 admissible 합니다.

### 요약표

| 환경 | 이동/간선 | A* 휴리스틱 | admissible? | 최적 보장 |
|---|---|---|---|---|
| 격자 | 4방향 | 맨해튼 `dx+dy` | O (가장 tight) | O |
| 격자 | 4방향 | 유클리드 `√(dx²+dy²)` | O | O |
| 격자 | 8방향 | 맨해튼 `dx+dy` | **X (과대추정)** | **X** |
| 격자 | 8방향 | 유클리드 `√(dx²+dy²)` | O | O |
| 그래프 | 가중치 간선 | `k × 노드 좌표 유클리드 거리` | O (consistent) | O |

## 코드 구조

```
index.html          화면 레이아웃
css/style.css       스타일
js/i18n.js          한국어/English 번역 사전과 언어 전환 (tr(ko, en))
js/algorithms.js    ★ Dijkstra, A* 구현 (이진 힙, 의사코드, 연산 단위로 상태를 yield 하는 제너레이터)
js/environments.js  ★ 격자(GridMap, gridProblem) / 그래프(GraphMap, graphProblem): 이웃·가중치·휴리스틱, 그래프 편집
js/app.js           캔버스·힙 트리 그리기, 애니메이션, 편집 도구, 키보드 입력
```

- 두 알고리즘은 `problem.neighbors(u) → [{to, w}]` 인터페이스만 사용합니다. 그래서 격자와 그래프에 **같은 Dijkstra/A* 코드**가 그대로 적용됩니다.
- Dijkstra와 A*는 "우선순위 키(dist 또는 f = g + h)"만 다르므로 공통 골격 `bestFirstSearch`에 구현했습니다. `dijkstra()`는 h ≡ 0, key = dist로, `astar()`는 key = f, 동점이면 h가 작은 쪽으로 호출합니다.
- 제너레이터는 의사코드 연산 하나마다 상태 `S`를 yield 합니다. `S.op`에는 연산 이름, 계산식, 의사코드 줄 번호가, `S.pq`에는 힙 배열이 그대로 들어 있습니다. 화면은 이것을 그리기만 합니다.
